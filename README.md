# صفحة قرية أبو بدوي — مصدر المحتوى للتطبيق

هذه المجلد هو كل ما يُرفع إلى GitHub Pages. التطبيق لا يخزّن أي محتوى داخليًا؛
كل الأقسام والعناصر تأتي من ملفات JSON هنا، والصفحة HTML تعرض نفس البيانات
بصيغة مقروءة للإنسان ومعلَّمة صراحةً ليقرأها التطبيق.

## بنية `data/index.json`

```jsonc
{
  "schemaVersion": 1,
  "generatedAt": "2026-09-28T06:00:00Z",
  "notice": "نص شريط أعلى الصفحة (صيانة/توقف مؤقت)، أو احذفه.",
  "brand": { "name": "قرية أبو بدوي", "tagline": "…", "logoUrl": "assets/logo.svg",
             "primaryColor": "#00696E", "supportEmail": "you@example.com" },
  "digest": { "defaultSections": ["village_news"], "hour": 7, "minute": 30 },
  "prices": { "fxUrl": "data/prices/fx.json", "goldUrl": "data/prices/gold.json",
              "liveFxApi": "…", "liveGoldApi": "…" },
  "location": { "name": "مركز بيلا، كفر الشيخ", "latitude": 31.1728,
                "longitude": 31.2210, "timezone": "Africa/Cairo" },
  "legal": { "privacy": { "title": "سياسة الخصوصية", "url": "data/legal/privacy.json" },
             "terms":   { "title": "شروط الاستخدام", "url": "data/legal/terms.json" } },
  "sections": [
    { "id": "village_news", "title": "أخبار القرية", "icon": "newspaper",
      "layout": "list", "order": 40, "home": true, "enabled": true,
      "source": { "kind": "json", "url": "data/sections/village_news.json" },
      "notifications": { "default": true, "breaking": false } }
  ]
}
```

الحقول الاختيارية لقسم: `subtitle`، و`image` (صورة غلاف تظهر في رأس شاشة القسم بالتطبيق؛
تُرفع من اللوحة وتُخزَّن في `sections.cover_image`)، و`source.kind` أحد
`json | html | rss | fx | gold | inline | prayer | weather | converter | calendar`، و`inlineItems` عندما يكون المصدر `inline`،
و`"managedBy": "admin"` التي تعني أن لوحة الإدارة هي التي تكتب هذا الملف (انظر قسم لوحة الإدارة).

كتلة `location` اختيارية: يحفظها الناشر من `app_settings.location`، ومنها يحسب التطبيق
مواقيت الصلاة والتقويم الهجري ويجلب الأرصاد. إن غابت أو كانت إحداثيات غير صالحة يستخدم التطبيق
موضع القرية الافتراضي (مركز بيلا، كفر الشيخ) — فلا يكسر حذفُها شيئًا.

### إضافة قسم جديد دون تعديل التطبيق

1. أضف عنصرًا إلى `sections` بـ `id` لاتيني فريد و`order` و`icon` من الأيقونات المعروفة
   (`newspaper`, `landmark`, `person`, `currency`, `gold`, `sell`, `ads`, `trophy`, `public`,
   `info`, `memorial`, `emergency`, `jobs`, `fixes`, …). القائمةُ الكاملةُ في
   `sectionIcon()` بالتطبيق (`ui/common/SectionIcons.kt`)، وهي نفسها في `ICONS` بلوحة `js/db.js`.
2. أنشئ `data/sections/<id>.json`.
3. ارفع الملفين. التطبيق يرسم القسم تلقائيًا في الرئيسية والدرج والإشعارات.
4. لإخفاء قسم مؤقتًا: `"enabled": false` — لا يحتاج حذفًا ولا إصدارًا جديدًا.

### قسم «تطبيقاتي» (`layout: apps`)

ثلاث اصطلاحات تجعل العنصر تطبيقًا لا خبرًا، بلا تعديل في التطبيق:

- **الصورة** — أيقونة التطبيق: مربّعة لا تضيق عن 192×192، تُرفع من اللوحة أو يوضع رابطها المباشر.
- **رابط خارجي** — صفحة المتجر أو أي رابط يخص التطبيق؛ يرسمه التطبيق زرَّ «افتح التطبيق»
  فيرسل الرابط إلى نظام التشغيل، فلا إذن جديد ولا تنزيل داخل التطبيق.
- **حقل `المميزات`** — سطر واحد تفصل الفواصل بين مزاياه (`،` أو `,` أو `؛` أو `|`)، فيعرضها
  التطبيق سطورًا تحت الوصف: أول ستٍّ في البطاقة، والبقية في صفحة الوصف عند النقر عليها.

بقية الحقول (`المطوّر`/`الحزمة`/`آخر تحديث`…) تظهر أسطرًا بعد المميزات، والنقر على البطاقة
يفتح الوصف كاملًا بكل المرفقات. البذرة الجاهزة في `supabase/sql/my-apps-section.sql`.

### قسم «قنوات البرمجة» (`layout: channels`)

بنفس بساطة `apps`، لكن للروابط الخارجية: بطاقة لكل قناة بشعارها (أو رمز دائري
إن تُركت الصورة فارغة)، وشارة المنصة المحسوبة من الرابط (يوتيوب/تليجرام/فيسبوك/
تيك توك/إنستجرام/إكس/واتساب، وما عداها «الموقع»)، والوصف، ووسوم المواضيع، وزر
«افتح القناة على يوتيوب» يرسل الرابط إلى نظام التشغيل — فلا إذن جديد في التطبيق،
ولا WebView، ولا تتبّع. بالنقر على البطاقة يفتح الوصف كاملًا كالعادة.

- **الاصطلاحات**: `الرابط الخارجي` = صفحة القناة، و`الوسوم` (أو حقل `المواضيع`)
  = مواضيعها، و`حقول إضافية` = اللغة والفئة العمرية ومعرّف القناة `UC…`.
- **الروابط**: لا تُنشر قبل فتحها والتأكد منها؛ معرّف القناة يبقى مرجعًا إن غيّر
  صاحبها الاسم المستعار. البذرة الموثّقة (ست قنوات عربية لتعليم الأطفال) في
  `supabase/sql/code-channels-section.sql`.
- **المسؤولية**: التطبيق يعرض روابط ولا يتحكّم في محتوى القنوات، فتختم البطاقات
  بسطر `channels_disclaimer` يوصي بمتابعة الأبناء.

### قسم «أرقام الطوارئ» (`layout: directory`)

صفحةُ دليل لا قائمةُ أخبار: سطرٌ لكل جهة باسمها ووصفها، وتحتهما الرقمُ كبيرًا
وزرَّ «اتصل». الزرُّ يرسل `tel:` إلى هاتف النظام (`ACTION_DIAL`) فيفتح الطلب
جاهزًا ولا يتصل وحده، فلا إذنَ اتصالٍ جديد في التطبيق.

- **الاصطلاح الوحيد الذي يقرؤه التطبيق**: حقل **`الرقم`**. هو ما يُعرض كبيرًا وما
  يُطلب عند الضغط على «اتصل». غابَ الحقل ظهر السطر عاديًا بلا زرٍّ — تُستعمل هذه
  للتنبيه الذي لا رقمَ فيه. بقية الحقول (`الجهة`/`متاح`/`من`) تظهر في صفحة
  العنصر عند النقر على السطر.
- **الأرقام كما تُكتب**: الأرقامُ الهندية مقبولة، يحوّلها التطبيق إلى لاتينية قبل
  العرض والطلب، والمسافاتُ والشرطاتُ تُطوى ولا يبقى إلا الأرقام وعلامة `+` (لأن
  النطاق الدولي يُنشر أحيانًا `‎+20 122 …‎`). لا تُدخل شرطةً في حقل الرقم معتقدًا
  أنها ستظهر: ستُحذف قبل الطلب.
- **إضافة رقمٍ جديد**: أضف عنصرًا في اللوحة (العناصر ← جديد ← القسم: أرقام الطوارئ)
  واكتب الرقم في حقل `الرقم`، وينشره الناشر في جولته التالية كلَّ خمس دقائق. لا
  تعديل في التطبيق ولا رفع نسخة APK — هذا كلُّ ما في «يقبل الإضافة لاحقًا».
- **التحقق قبل النشر، لا بعده**: البذرة في `supabase/sql/emergency-numbers-section.sql`
  رقّمت اثني عشر رقمًا بعد مطابقة كلِّ رقمٍ على مصدرين، وأصلحت ثلاثة أخطاءٍ في صفحة
  المصدر (رقمُ الغاز ١٢٩ كان ناقصًا، و«الكوارث الطبيعية ١٢١» و«السيارات الكهربائية
  ١٩٩٩٤» لم يتحققا). لا تُعدّل رقمًا ولا تُضف واحدًا قبل أن تثبت من مصدرين: هذه
  الشاشة تُفتح في لحظةٍ لا احتمالَ فيها لرقمٍ خاطئ. فحصُ التحقّق في نهاية الملف
  يُنبّه إلى كل عنصرٍ بلا `الرقم` أو في رقمٍ حروفٌ سواها.

### قسم «فرص عمل» (`layout: jobs`)

لوحةُ إعلانات توظيف، لا قائمةُ أخبار: بطاقةٌ لكل فرصة بمسمّاها وجهتها ورقائقِ
مجالها وموقعها ونوع عملها، وسطرُ الراتب والخبرة وعدد المطلوب، فموعدُ التقديم
الأخير وعدّادُه («بعد ٦ أيام»). الترتيبُ موعدٌ منشورٌ لا مكانةُ وظيفةٍ في سوقٍ
لا تقيسه التطبيق.

- **الحقول التي يقرؤها التطبيق** (بأسمائها أو مرادفاتها): `الجهة` (أو `الشركة`
  /`صاحب العمل`)، `المجال` (`القطاع`/`التخصص`)، `الموقع` (`مكان العمل`/`المكان`)،
  `النوع` (`طبيعة العمل`/`نوع العقد`)، `الراتب` (`الأجر`/`المقابل`)، `الخبرة`
  (`السن`)، `عدد المطلوب` (`العدد`)، `التقديم` (`طريقة التقديم`/`للتقديم`)،
  `آخر موعد` (`الموعد الأخير`/`يغلق`). غابَ حقلٌ غابَ سطرُه، ولا جهةَ تُختلق ولا
  راتبًا يُقدَّر.
- **الموعدُ هو عمر الإعلان**: يُقبل `2026-11-05` و`٥/١١/٢٠٢٦` كما يُقبل الجدول
  الدراسي. يومُ الموعد نفسِه ما زالت الفرصةُ تُقبل، وفي الغد تُطوى تحت زرِّ
  «انقضت مهلتها (٣ فرص)» بدل أن تختفي. و`آخر موعد` غابَ بقيت الفرصةُ حيّةً بلا
  يوم، فلا يُفتَرَض لها إغلاقٌ لم ينشره صاحبُه.
- **التقديم**: زرُّ «التقديم عبر الرابط» يظهر للرابط المنشور وحده — `الرابط
  الخارجي` للعنصر أو حقل `الرابط`؛ يُرسَل الرابط إلى نظام التشغيل كما في `apps`
  و`channels`، بلا WebView ولا تتبّع. أمّا حقل `التقديم` فسطرٌ يصف العنوان أو
  البريد كما كتبه المعلن، ولا يحوّله التطبيق إلى زر.
- **إضافة فرصةٍ جديدة**: عنصرٌ في اللوحة (العناصر ← جديد ← القسم: فرص عمل) ثم
  نشرٌ في جولة الناشر كلَّ خمس دقائق. لا تعديل في التطبيق ولا رفع APK — وحين
  تنقضي المهلة يكفي تغييرُ `آخر موعد` أو أرشفةُ العنصر.
- **البذرة لا تحمل فرصةً واحدة** (`supabase/sql/jobs-section.sql`): تُوسّع قيد
  `sections_layout_check` ليقبل `jobs` وتنشئ صفَّ القسم بلا عناصر، لأن الفرصة
  الوهمية يدفع إليها الناس طلباتٍ وأوقاتًا، والفراغُ هنا يقول «لم تُنشر بعد» لا
  «لا عمل في القرية».
- **بلا إعلانٍ مموّل**: مثل `campaigns`، لا تُدخل بطاقة AdMob بين فرصتَين؛
  «إعلان» بجوار إعلان توظيف يُوحي بأن المعلن يوظّف.
- **على النسخ القديمة**: من لم يحدّث يرى القسم `list` عاديًا بلا خطأ، لأن
  `Layout.from()` يسقط كل تخطيطٍ لا يعرفه إلى القائمة. البذرة والقيود في
  `supabase/sql/jobs-section.sql`.

### قسم «حلول مشاكل الموبايل» (`layout: fixes`)

لوحةُ أعطالٍ وحلولِها، لا قائمةُ أخبار: بطاقةٌ لكل مشكلةٍ بعنوانها وعلامةِ عطلها
(أو لصيانةٍ تقيها ذلك العطل)، وسببها المنشور، وخطواتِها مرقّمةً ١-٢-٣، ورقائقِ صعوبتها
ووقتها وأجهزتها، وسطرِ
تنبيهٍ بأيقونة خطأ، وزرِّ «شاهد فيديو الإصلاح» يفتح الشرح عند صاحبه، وزرٍّ ثانٍ للتحميل
إن نشر صاحبُ الحلّ تطبيقًا في حقل «التطبيق». الترتيبُ ترتيبُ
الناشر: لا مقياسَ عند التطبيق يقيس أيَّ حلٍّ أنفعُ لقارئٍ لا يعرف جهازه.

- **الحقول التي يقرؤها التطبيق** (بأسمائها أو مرادفاتها): `النوع` (`الفئة`/`الباب`)
  وهو محور التصفية، `السبب` (`الأسباب`)، `الخطوات` (`الحل`/`الطريقة`)، `الصعوبة`
  (`مستوى الصعوبة`)، `الوقت` (`المدة`/`الوقت التقريبي`)، `الأجهزة` (`الجهاز`/`النظام`)،
  `تنبيه` (`تحذير`/`ملاحظة`). غابَ حقلٌ غابَ سطرُه، ولا خطوةَ يكتبها التطبيق من عندَه.
- **الخطوات تُفصل بـ`؛` أو سطرٍ جديد أو `|`**: الناشرُ يضغط المسافات في `fields` إلى
  فراغٍ واحد ويقتطع كلَّ قيمةٍ بعد ٤٠٠ حرف، فلتكن الخطواتُ على البطاقة مختصرةً،
  والتفصيلُ كاملًا في `body` (يُقبل `<ol><li>`) الذي يفتحُه زرُّ «تفاصيل الحل».
  ومن اللوحةِ لا سطرَ لحقلٍ واحد — سطرٌ جديدٌ في مربع «حقول إضافية» معناهُ حقلٌ
  جديد — فالفصلُ هناك بـ`؛` أو `|`، وقيمةٌ كُتبت على أسطرٍ في القاعدة تدمجُها اللوحة
  عند التحرير إلى سطرٍ واحد بـ`|` حتى لا تضيع خطواتُها. القطعُ لم يعد صامتًا:
  الحادي عشر من الحقول، والقيمةُ المتجاوزةَ أربعمئة حرف، واسمُ الحقلِ المطوَّل،
  وأنْ يزيدَ القسمُ على ثمانين عنصرًا فيقطَع الناشرُ الزائدَ — كلها `-- NOTICE:` في سجل التشغيل، وتُعدَّد
  في رسالة آخر جولةٍ في لوحة «سجل النشر» وتُلوِّنها `partial`. أمّا الحلُّ بلا نسبةٍ
  كاملة فملاحظةٌ وحده: تُطبع وتُعدّ ولا تُلوِّن الجولةَ ولا تمنع النشر.
- **الفيديو رابطٌ لا مشغّل**: `الرابط الخارجي` للعنصر (أو حقل `الفيديو`) يُرسَل إلى
  نظام التشغيل كما في `apps` و`channels` — بلا WebView ولا استضافةٍ على خادم القرية.
  غابَ غابَ زرُّه، ولا يُستضاف فيديوٌ هنا ليُشاهَد داخل التطبيق.
- **الخطواتُ تُنقلُ لا تُؤلَّف**: مصدرُها الفيديو نفسُه — تفريغُه الصوتي حين يكون له
  نصٌّ (يُفتح من صفحةِ العنصر)، ولقطاتُ شاشةٍ منه حين لا نصَّ فيه كما في لوحةِ تحكمِ
  الراوتر حيث القوائمُ إنجليزيةٌ كما تظهرُ على الشاشة. لا تُستبدلُ تسميةُ «Encryption
  Settings» بشرحٍ عربيٍّ لها، ولا تُخترع خطوةٌ لم تُرَ أو تُسمَع.
- **التطبيقُ زرٌّ ثانٍ لا بديلٌ للفيديو**: `رابط التطبيق` (`التطبيق`/`التحميل`/`التنزيل`)
  رابطُ متجرٍ ينشره صاحبُ الحلّ، فيأخذ بطاقةُ الحلّ زرَّ «حمّل تطبيق …» إلى جوار زرِّ
  الفيديو، ولا يختار التطبيقُ متجرًا لم يُنشر. `اسم التطبيق` يسمّي الزرَّ؛ غابَ بقي
  «حمّل التطبيق» مبهَمًا، والفحصُ في نهاية الملف يُنبّه إليه. قيمةٌ في `التطبيق` ليست
  http(s) لا تُنشئ زرًّا أصلًا.
- **النسبةُ واجبة**: الفيديو عند صاحبه، فيُكتب `اسم المصدر` (`source_name`) ورابطُه
  كما هو، وفحصُ التحقّق في نهاية الملف يُنبّه إلى كل حلٍّ ينشر فيديو بلا اسمِ صاحبه.
- **الصور المولَّدة**: أغلفةُ العناصر الثمانية المنشورة (`assets/fix-annoying-ads.webp`
  و`assets/fix-force-restart.webp` و`assets/fix-auto-restart.webp`
  و`assets/fix-change-location.webp` و`assets/fix-weak-sound.webp`
  و`assets/fix-charging-port.webp` و`assets/fix-wifi-password.webp`
  و`assets/fix-router-lamps.webp`) كلها ١٠٢٤×٥٨٥
  بأحجام ‎31KB و27KB و23KB و28KB و33KB و38KB و23KB و17KB،
  وكلُّها رسمٌ مُولَّد بالذكاء الاصطناعي لأغراض هذا القسم لا لقطةٌ من الفيديو،
  و`حقل النسب` (`image_credit`) يقول ذلك صراحةً. أضف غلافًا جديدًا بملفٍ في
  `assets/` ومسارٍ نسبيٍّ في عمود `image`، فيحوّله التطبيق إلى رابطٍ كامل مقابل
  `baseUrl` كما يحوّل `assets/village.svg`.
- **إضافة حلٍّ جديد**: عنصرٌ في اللوحة (العناصر ← جديد ← القسم: حلول مشاكل الموبايل)
  ثم نشرٌ في جولة الناشر كلَّ خمس دقائق. لا تعديل في التطبيق ولا رفع APK. اختر القسم
  بالاسم في محرّر العنصر فتظهر تحتَه بطاقةُ عقدِ `fixes` كاملة: أسماءُ الحقول
  ومرادفاتُها، وفاصلُ الخطوات، وحدودُ عشرةِ الحقول وأربعمئةِ الحرف، وشرطُ النسبة —
  فلا يُطلب من المحرّر حفظُ هذا الملف ولا معرفةُ شيءٍ من كود التطبيق. بطاقةُ الحدود
  والقطعِ تسري على كل تخطيط، أمّا عقدُ الأسماء فقد وُصف هنا لقسم الحلول خاصةً.
- **لا يزاحم «أحدث المنشورات»**: التطبيقُ يُخرج تخطيط `fixes` من معاينة الرئيسية كما
  يُخرج `jobs` و`directory` — الحلُّ خدمةٌ لها شاشتها وخطواتُها، لا خبرٌ يُقرأ سطرٌ منه
  في الرئيسية ثم يُنسى.
- **قاعدة النشر هنا أثقل من غيرها**: القارئ سيأخذ من الشاشة خطواتٍ يمسّ بها إعدادات
  هاتفه، فلا تُنشر خطوةٌ قبل تجربتها أو مصدرٍ يشرحها، ولا يُحذف `تنبيه` حين تمسح
  الخطوةُ بياناتٍ. التطبيقُ يقرأ الحلَّ ولا يُنفّذه: لا إذنَ يطلبه على جهازٍ، ولا
  صلاحياتٍ في Manifest لهذا القسم.
- **بلا إعلانٍ مموّل**: مثل `campaigns` و`jobs`، لا تُدخل بطاقة AdMob بين حلٍّ وحلٍّ؛
  «إعلان» في شاشةٍ عنوانُها التخلّصُ من الإعلانات المزعجة يُكذّب ما يقرأه صاحبُ الهاتف.
- **على النسخ القديمة**: من لم يحدّث يرى القسم `list` عاديًا بلا خطأ، لأن
  `Layout.from()` يسقط كل تخطيطٍ لا يعرفه إلى القائمة. البذرةُ والعناصرُ الثمانية
  وفحصُ التحقّق في `supabase/sql/mobile-fixes-section.sql`.

### قسم «محافظة كفر الشيخ» (`layout: list` — محتوى بلا كود)

عشرون عنصرًا list، كل عنصر جانب من معلومات المحافظة (الموقع والحدود، الطبوغرافيا،
المناخ، المراكز العشرة، السكان وتعداداتهم، التاريخ الإداري، الاقتصاد، الجامعة،
بحيرة البرلس، مصيف بلطيم، معركة البرلس، دسوق، العاصمة، الطرق، مركز بيلا، الأعلام،
المحافظون، بطاقة سريعة). لا تعديل في التطبيق ولا في اللوحة ولا في الناشر: تخطيط
`list` ومصدر `json` يعملان من قبل، فالتسليم كله في `supabase/sql/governorate-section.sql`.

- **المصدر إلزامي**: ويكيبيديا نصّها مرخّص CC BY-SA 4.0 ويلزمها النسب، لذلك كل عنصر
  يحمل `اسم المصدر` و`رابط المصدر` إلى مقالته، وفي آخر متنه جملة «المصدر»، وزر
  «افتح المصدر» في صفحة العنصر يفتح المقالة. المتن ملخَّص لا منسوخ حرفيًا.
- **الصور**: كلها من ويكيميديا كومنز برخصة حرة، و`حقل النسب` (`image_credit`) يكتب
  المرخّص والرخصة، والتطبيق يعرضه تحت الصورة دائمًا. أي صورة تُضاف لاحقًا بلا نسب
  يرفعها فحص التحقّق في نهاية الملف تحذيرًا.
- **ما تضارب في المصدر ذُكر كما هو**: تعداد 2015 ورد في المقالة على رقمين
  (3,172,753 في الصندوق و3,941,293 في المتن) فيعتمد رقم 2024 (3,740,624) ويُذكر
  الآخران؛ وكذلك «13 مدينة» مقابل 14 في الصندوق، وعرض بوغاز البرلس في مقالة
  المحافظة مقابل مقالة البحيرة.
- **التقادم**: اسم المحافظ يتغيّر بقرار جمهوري، وعدد السكان تُحدِّثه التقديرات؛
  عنصر «محافظو كفر الشيخ» يشرح هذا صراحةً في آخر متنه، فحدِّثه من اللوحة عند الشك
  بدل إعادة تشغيل الملف (إعادة التشغيل لا تغيّر عنصرًا موجودًا).

### قسم «قصص الأنبياء» (`layout: list` — خمسٌ وعشرون قصّةً منقولةً، لا مُعَدة)

الترتيبُ ترتيبُ كتابِ ابن كثير: آدم، فإدريس، فنوح، … حتى عيسى عليه السلام. لا تعديل في
التطبيق ولا في الناشر ولا في اللوحة: تخطيط `list` ومصدر `admin` يعملان من قبل. البذرةُ في
`supabase/sql/prophets-section.sql`، ومولِّدها `tools/gen-prophets-sql.mjs` في مستودعِ
التطبيق (يقرأ نسختَي ويكي مصدر من `out/*.wiki` وبلاهما يجلبُهما)، و`--sql` وحده يكتب الملف.

- **المصدرُ موثوقٌ ومُرخَّصٌ، وهو مكتوبٌ في العنصرِ لا في الوصف**: «قصص الأنبياء» لابن كثير
  (ت ٧٧٤هـ) من ويكي مصدر — نسخةٌ منقولةٌ عن مطبوعةٍ مُحقَّقة (`{{مطبوعة}}` في رأسِ كلِّ
  صفحة)، ورخصةُ الموقعِ CC BY-SA 4.0 كما تُعلنُها الواجهةُ نفسها (`meta=siteinfo&siprop=rightsinfo`)،
  ونصُّها مكتوبٌ في حقلِ `الرخصة` وفي آخرِ المتن. النسبةُ في كلِّ بطاقةٍ، لا في مقدمةِ القسمِ فقط.
- **لا تأليفَ فوقَ النصِّ**: البطاقةُ آياتٌ منقولةٌ ثم سردٌ متَّصلٌ كما هو في الكتابِ —
  فقراتٌ متتاليةٌ من البابِ نفسه بمقدارِ ما يُقرأ دفعةً واحدة، لا مقطوعةٌ مُفَصَّلة.
  ويُذكرُ رقمُ البابِ والجزءِ في حقلِ `الباب`، ورابطُ العنصرِ يفتحُ الصفحةَ على مرساةِ
  البابِ لا على رأسِ الجزءِ (المعاريفُ تُقرأُ من الصفحةِ المنشورةِ نفسِها وتُخزَّنُ في
  `out/prophets-anchors-vol*.json`؛ تغييرُ عنوانٍ في ويكي مصدر يُظهر `-- WARNING` عند التوليد).
- **البابُ إذا لم يسعَ نبيًّا**: لا فصلَ ليعقوبَ في الكتابِ وحدَه، فهو داخلَ بابِ أبيه
  إسحاق، وبابُ إلياسَ داخلَ «قصتي الخضرِ وإلياس» — فالمرجعُ في الحقلِ صادقٌ لا مُجمَّل.
- **أرقامُ الآياتِ محقَّقةٌ بالآليّة**: المولِّدُ يطابقُ كلِّ آيةٍ مع ألفاظِ البابِ الذي
  نُقلت منه (بعد طيِّ التشكيلِ وحروفِ المدِّ، لأنَّ «صديقا» في المطبوعةِ و«صدقا» في الرسمِ
  العثمانيِّ حرفٌ واحدٌ مختلف). `-- NOTICE` يعني أنَّ البابَ يوردُ بعضَ الآية، و`-- WARNING`
  يعني أنَّها لا تُقرأُ فيه كلَّه؛ والباقي أربعُ آياتٍ (٥٤:١٤، ٥١:٢٨، ١٩:١٢–١٣) صحيحةُ في
  شأنِ صاحبِها لكنها في بابٍ آخرَ من الكتابِ أو في القرآنِ وحده، لذلك عنوانُ القطعةِ
  «آياتٌ من القرآنِ في شأنِه» لا «في هذا الباب».
- **الترتيبُ بلا جرسِ إشعار**: كلُّ العناصرِ على `published_at` واحد، فيحفظُ الناشرُ ترتيبَ
  الكتابِ (فرزٌ مستقرٌّ على `sort_order` تنازليًّا، كما في `governorate`)، ولا تُقرأ القصصُ
  كأنَّها نزلت اليوم. و`show_on_home: false`: البطاقةُ في «الأقسامُ» لا في «أحدثِ المنشورات»،
  فخمسةٌ وعشرون عنصرًا بتاريخٍ واحدٍ تُزاحمُ أخبارَ القريةَ ولا خبرَ فيها — كما يُفعَلُ مع
  `quran_download` و`sahihayn`.
- **الكتابُ نفسه يُنبَّه عليه**: ابنُ كثيرٍ ينقلُ عن أهلِ الكتابِ وإسرائيلياتٍ ويضعفُها،
  وحقلُ `note` في القسمِ يقولُ ذلك للقارئ لا للوحة: الحُجَّةُ الآيةُ الصحيحةُ لا الحكايةُ وحدها.

### أخبار العالم والرياضة: `news.yml` يجلب وينشر في نفس التشغيل

أقسام «أخبار عالمية» (`world_news`) و«أخبار الرياضة» (`sports`) و«أخبار كفر الشيخ»
(`local_news`) لا تُحرَّران يدويًا كل يوم: `scripts/sync-news.mjs` يجلب خلاصات RSS عربية
رسمية وأخبار محافظة كفر الشيخ من بوابتها الرسمية كل ١٥ دقيقة ويكتب العناصر في
جدول `items` — فيبقى مصدر الحقيقة واحدًا (القاعدة)، وتراه اللوحة وتحرّره كأي عنصر.

| التغذية | القسم | الصورة |
|---|---|---|
| بي بي سي عربي | عالم | `media:thumbnail` |
| فرانس 24 | عالم | `media:thumbnail` + `enclosure` |
| سكاي نيوز عربية | عالم (ورياضة لما كان المسار `/sport`) | `enclosure` |
| الجزيرة نت | عالم (ورياضة لما كان المسار `/sports`) | `og:image` من الصفحة |
| سبوتنيك عربي | عالم | `og:image` من الصفحة |
| سي إن إن عربي | عالم | `media:thumbnail` |
| روسيا اليوم عربي | عالم | `media:thumbnail` |
| الرياضية | رياضة | `main_image` |
| البوابة الرسمية `kfs.gov.eg` | محلّي (صفحتان من «أخبار المحافظة») | الصورة المصغّرة في القائمة |

- **المِلكية**: كل عنصر آلي يبدأ الslug عنده بـ `rss-` (بصمة الرابط)، فلا يمسّ السكريبت
  عنصرًا كتبه ناشر القرية. الفلترة تتم بالبادئة في JS بعد قراءة القسم كاملًا، لا بفلتر
  `like` في REST (النقطة فيها حرف لا وايلد، وهو ما ضاعف الأخبار جولةً كاملة)، وتُحذف أي
  نسخ مكرّرة تلقائيًا — وضبط `supabase/sql/rss-slug-unique.sql` يمنع المكرّر بقيد في القاعدة.
  وللمدراء سيطرة تبقى بعد كل جولة: `pinned` و`breaking` لا تُرسل في التحديث،
  و`status = archived` تعني «لا تُحدّث هذا الخبر أبدًا».
- **أربعة في البطاقة**: العنوان في `title`، والملخص في `subtitle`، والصورة في `image`
  مع نسبها في `image_credit`، ورابط المصدر في `link` + `source_name` + `source_url`
  — وهو زر «افتح المصدر» في صفحة العنصر، فيقرأ القارئ الخبر عند من كتبه.
- **حدود معقولة**: ٤٠ عنصرًا لكل قسم في الجولة، و١٢ لكل تغذية حتى لا يبتلع مصدرٌ القسم،
  وأحدث ٦٠ فقط تُبقى في القاعدة (الناشر ينشر ٨٠ بحدّه `MAX_ITEMS`)، ولا خبر عالمي أو
  رياضي أقدم من أربعة أيام — وأخبار البوابة الرسمية تُقبل إلى ستة أشهر، لأن إعلانًا عن
  قرار أو مشروع يبقى مفيدًا أسابيع. الصور الناقصة تُجلب من `og:image` بحدّ ١٢ صفحة في
  الجولة وتُخزَّن في `link_previews` فلا يُجلب رابط مرتين.
- **NewsAPI اختياري**: الخطة المجانية ١٠٠ طلب/يوم والدورية ٩٦ جولة، فيُستقصى في أول ثماني
  دقائق من كل ساعة فقط (٤٨ طلبًا/يوم)، وبحث المحافظة — وهو `/v2/everything` بكلمات كفر
  الشيخ — مرة كل ست ساعات (~٥٦ طلبًا/يوم مجموعًا). بلا `NEWS_API_KEY` في الأسرار يعمل
  النظام بالخلاصات والبوابة الرسمية وحدهما، وهذا يكفي؛ لا يوضع المفتاح في التطبيق ولا في
  اللوحة أبدًا. ولأن كرون هذا المستودع متأخر، فالنافذة تسقط أحيانًا فتُحرم المحافظة من
  بحثها يومًا كاملًا؛ لذا في `news.yml` input يدوي `force_newsapi` يتخطّاها عند الطلب —
  أما الجدول فلا يتخطّاها، فلا تتجاوز الحصة نفسها.
  وملاحظة صراحةً: الخطة المجانية من NewsAPI مرخّصة للاستخدام غير التجاري،
  فالبقاء تحتها يعني ألاّ نسخٍ إضافي للمحتوى ولا بيع له — والمطلوب منها هنا عنوان وزرّ
  «افتح المصدر» لا أرشيف مقالات.
- **التأخير الظاهر**: لا يوجد — `news.yml` يشغّل `publish.mjs` ويدفع `data/` في نفس التشغيل،
  فالخبر يصل التطبيق خلال دورته. يبقى `publish.mjs` هو المولّد الوحيد للملفات في الحالتين،
  فلا مصدر الحقيقة الثاني غير القاعدة.
- **جدولة GitHub متأخرة فعليًا**: الكرون هنا لا يحترم توقيته؛ `publish.yml` المجدول كل خمس
  دقائق شُغِّل جدوليًا سبع مرات في يومين (قياس ٢٠٢٦-١٠-٠٤). لذلك يضيف `news.yml` «تتابعًا»:
  كل تشغيل ينتظر حدّ الربع ساعة ثم يرسل `workflow_dispatch` لنفسه، فيصير الدور كل ١٥ دقيقة
  مهما تأخر الكرون. التتابع اختياري: يتفعّل بمجرد إضافة سرّ `RELAY_TOKEN` (مفتاح شخصي
  من نوع fine-grained، صلاحيته Actions: Read and writes على هذا المستودع وحده). بدونه يعمل الكرون وحده.
- **تحقّق قبل النشر**: `node .github/scripts/sync-news.mjs --dry-run` يطبع ما سيُكتب بلا
  كتابة، و`--section=sports` أو `--section=local_news` لقسم واحد، و`--no-newsapi` يترك
  NewsAPI جانبًا، و`--force-newsapi` يسألها الآن بلا انتظار النافذة (للتشغيل اليدوي).

### قسم «أخبار كفر الشيخ» (`local_news`): مصادر لا تخالف سياسة أحد

المحافظة لا تُذكر في خلاصات الوكالات يوميًا، فالقسم مبني على ثلاث طرق كلها استخدام
مسموح به صراحةً، لا استخراج من صفحات ولا من شبكات اجتماعية:

1. **البوابة الرسمية للمحافظة** `https://kfs.gov.eg/posts?category=akhbar-almhafth` —
   robots.txt عندها سطر `Disallow:` فارغ، أي أن صاحب الموقع يأذن لكل زائر بكل مساراته،
   والصفحة قائمة معلنة البنية (`post-card`/`card-title`/`card-excerpt`/`meta-date`).
   يُؤخذ منها العنوان، والمقتطف الذي كتبه ناشر الموقع نفسه وقصّه بثلاث كلمات، ورابط
   الخبر، وصورته المصغّرة، وتاريخه. لا تُفتح صفحة الخبر أصلًا. المصدر يُذكر في
   `source_name` و`source_url`، فيبقى النسب ظاهرًا في البطاقة.
2. **فلتر كلمات المحافظة على الخلاصات المرخّصة أصلًا** — الخبر الذي تذكره بي بي سي أو
   سكاي نيوز أو سي إن إن عربي عن كفر الشيخ يُنسخ نسخته نفسها إلى هذا القسم (بنفس
   بادئة الslug وبذكرة المصدر)، فيغطي ما ينشر عن المحافظة في صحف أخرى.
3. **NewsAPI بحثًا بالكلمات** (`/v2/everything?q="كفر الشيخ" OR دسوق OR …`) — واجهة
   رسمية بمفتاح، وشروطها تطلب ذكر المصدر والربط إلى المقال، وكلاهما مكتوب في البطاقة.

الكلمات تُطابَق على نص موحَّد الصورة (تشكيل محذوف، همزات موحَّدة، فراغات موحَّدة)،
وبحدود عربية حقيقية: ما بعد الكلمة حرفٌ منعها (ف«فوه» لا تقع داخل «فوهة»، و«بيلا» لا
داخل «بيلاطس» ولا في «سبيلا»)، وما قبلها يُسامح إن كان حروف اتصال (ف«بالحامول» و
«والدسوق» خبر عن الحامول والدسوق). الأسماء التي لا يشتبه لفظها تقبل وحدها: كفر الشيخ
بصورتيها (بمسافة وبلا مسافة)، دسوق، مطوبس، الحامول، قلين، بلطيم، سيدي سالم، سيدي
غازي، البرلس؛ وما يشتبه (فوه، بيلا، الروضة، المثنى، شليمة، مرشد…) لا يقبل عنصرًا إلا
مع قرينة مصرية بجانبه («محافظة»، «محافظ»، «مصر»، «كفر»، «دلتا»).

- **الحقوق**: البطاقة عنوان + ملخّص قصير + مصدر + رابط. لا يُنقل متن الخبر ولا صورة من
  مقالة مدفوعة؛ وصورة البوابة الرسمية مصغّرتها المنشورة في قائمتها العامة.
- **القاعدة**: البذرة في `supabase/sql/local-news-section.sql` (قسم `list` بمصدر `json`
  وترتيب ٤٥، بعد أخبار القرية وقبل العالمية)، والتطبيق يقرأ الأقسام من `index.json`
  فيظهر القسم بلا نسخة APK جديدة — والأيقونة `place` معروفة في `SectionIcons.kt`.
- **ما متوقع من القسم**: البوابة الرسمية تنشر على فترات (قياس ٢٠٢٦-١٠-٠٤: أحدث بطاقتها
  من أواخر يونيو)، فتغذّيه الأساسي فعلاً بحث NewsAPI وفلتر الوكالات؛ إن لم يجد شيءٌ
  من الثلاثة اليوم بقيت أحدث البيانات الرسمية في القسم بدل أن يفرغ.
- **قياس الجولة الأولى** (تشغيل يدوي بـ `force_newsapi` في ٢٠٢٦-١٠-٠٤، سجل التشغيل):
  البوابة الرسمية ١٧ بطاقة، وفلتر الوكالات صفرًا، وبحث NewsAPI صفرًا — مع أن صحف
  المحافظات نشرت عن كفر الشيخ في اليوم نفسه. فالقسم اليوم رسميّ البنية لا يوميّها،
  وهذا مقصود: لا يُبنى على مصدرٍ مخالفٍ سياسته ليملأ الشاشة.
- **ما رُفض ولا يُعاد تجربته**: `news.google.com/rss/search` (يعطي تغطية المحافظة كاملة
  لكنه ممنوع صراحةً في robots عنده: `User-agent: *` / `Disallow: /` بلا إذن لمسار `/rss`)؛
  خرائط مواقع الصحف (`youm7.com/Sitemap/<year>/<month>/<day>` يعطي عنوان الخبر داخل
  الرابط، لكنه ردّ علينا دورة إعادة توجيه لا تنتهي بعد طلبٍ واحد ناجح — والرفض الفعلي
  أبلغ من الإذن النظري؛ و`dostor.org/sitemap/news.xml` روابطه أرقامٌ بلا عناوين)؛
  وواجهة GDELT المفتوحة (جرّبناها اليوم نفسه: ٤٢٩ من مشغّل Actions ومن هذا الجهاز،
  فحدودها تُطبَّق على عناوين السحابة ولا يُبنى عليها دورية — رجوعُ `db47233`).
  البديل المشروع الوحيد لتغطية يومية واسعة مصدرٌ مرخَّص بعقد (بوابة أخبار مدفوعة أو
  اتفاق مع ناشر)، وهو خارج خطة القرية المجانية.

### قسم «التقويم الهجري» (`layout: calendar`)

لا عناصر له ولا ملف تغذية: التطبيق يحسبه وحده من Aladhan بنفس `method=5` ومن نفس
`location` اللذين تحسب منهما مواقيت الصلاة، فلا يتناقض الشهر الهجري في التقويم مع
عدّاد المواقيت ولا مع إعلان دار الإفتاء المحلي.

- **الشبكة** — شهر ميلادي كامل يبدأ السبت (أول أيام الأسبوع في التقويم العربي)، وفي كل
  خلية اليوم الميلادي ففوقه نظيره الهجري. اليوم الحالي مميّز بلون الحشو الأساسي،
  والمناسبة بشرطة سفلى؛ والنقر على الخلية يملأ خانات التحويل باليوم المختار.
- **المناسبات** — جدول عربي منتقى في التطبيق (`OCCASIONS`) مفتّح بيوم الشهر الهجري
  وشهره: رأس السنة الهجرية، عاشوراء، المولد النبوي، الإسراء والمعراج، ليلة البراءة،
  أول رمضان، ليلة القدر، عيد الفطر، يوم عرفة، عيد الأضحى وأيام التشريق. تظهر في الشهر
  قائمةً مستقلة تحت الشبكة بتاريخها الميلادي، لأن قائمة الأعياد التي يرجعها Aladhan
  إنجليزية ومزدحمة بملاحظات فقهية لا تصلح للعرض.
- **التحويل** — اتجاهان (ميلادي ← هجري وهجري ← ميلادي) باسم اليوم العربي في النتيجة،
  بخانات شهر وسنة تنقل كاملًا. الحساب تقديري، والشهر الهجري ثبوتُه بالرؤية؛ النص
  `calendar_disclaimer` يوضح ذلك أسفل الشاشة.
- **عند انقطاع الإنترنت** — يُخزَّن لكل شهر نصّ استجابته (`calendar.<yyyy-MM>.raw`) ولكل
  تاريخ محوَّل نسخته، فتُعرض آخر نسخة مع شارة «غير متصل» بدل أن تفارغ الشاشة.
- **التدريج** — نسخة قديمة من التطبيق لا تعرف `calendar` تعرض القسم كقائمة فارغة، والناشر
  القديم يحوّل تخطيطه إلى `list` بلا خطأ. البذرة والقيود في `supabase/sql/calendar-section.sql`.

### قسم «ولد صالح يدعو له» (`layout: memorials`)

تذكرة لكل من رحلوا: بطاقة فيها اسم المتوفّى، وتاريخ وفاته في التقويمين، وما مضى عليه،
والدعاء له، وزر يشارك الدعاء. الفكرة من حديث «…أو ولد صالح يدعو له»، فالقسم ذاكرة ودعوة
لا خبر نعي: لا ينقل اسمًا من صفحات النعي في الصحف (نصها مملوك لصحفها)، وكل بطاقة يدخِلها
الناشر من اللوحة بموافقة أهل المتوفّى.

- **الحقول** — `title` اسمُه، و`date` تاريخ وفاته (حقل «التاريخ كما يظهر» = `event_date`)،
  و`subtitle` كنية أو بلدًا تحت الاسم، و`image` اختيارية، و`fields` ما يحب توثيقه (العمر،
  مكان الدفن). الصيغة الكاملة `2026-10-04` هي وحدها التي تُحسب منها البقية؛ والناقصة أو
  النص الحر يظهر كما كُتب بلا تحويل ولا حساب.
- **الدعاء** — `body` العنصر إن كُتب، وإلا الدعاء الافتراضي `memorial_duaa_default` في
  `strings.xml` (صيغة المذكّر من دعاء النبي ﷺ في مسلم). لغير المذكّر يُكتب المتن:
  «اللهم اغفر لها وارحمها…»، فلا يخلط التطبيق بين صيغتين.
- **الحساب كله بلا إنترنت** — التاريخ الهجري بجدول أم القرى المضمّن في `java.time`
  (`HijrahDate`)، وما مضى من `Period`، والذكرى السنوية حين تبقى عشرة أيام فأقل عليها.
  وهو نفس تقويم أم القرى الذي يعرضه قسم «التقويم الهجري»، ويختلف عنه يومًا حيث يختلف
  ثبوت الشهر بالرؤية الشرعية.
- **نسخة التطبيق القديمة** التي لا تعرف `memorials` لا تفقد القسم: `Layout.from` يردّه إلى
  `list`، فتظهر الأسماء والتواريخ والدعاء المكتوب — رديئة الترتيب لا ناقصة المحتوى.
- **البذرة والقيود** — `supabase/sql/memorials-section.sql` يوسّع `sections_layout_check`
  ليقبل `memorials` ويزكي صف القسم؛ والقسم يحتاج نسخة APK جديدة لأن تخطيطه مرسوم في
  `ui/section/MemorialViews.kt`، لا لأنه غير معروف.

### قسم «مواعيد قطارات مصر» (`layout: trains`)

جدول الرحلات الداخلية: بطاقة لكل رحلة، يبحث فيها القارئ برقم القطار أو باسم أي محطة
(ولو وردت في الوقفات وحدها)، وتجمّع الرحلات خطوطًا («القاهرة ← الإسكندرية») مرتّبة
بأول القيام.

- **لماذا يدويًا؟** لا مصدر آليّ مسموح: `enr.gov.eg` يُرجع كل مساراته — ومنها `robots.txt`
  وصفحة الجداول — تحويلًا `302` إلى بوابة دخول، و`www.enr.gov.eg` لا يستجيب للاتصال، ولا
  توجد مجموعة بيانات مفتوحة عن المواعيد، ومرايا المواعيد التجارية نسخٌ منسّقة من إعلان
  الهيئة. الممنوع هو الجلب من الموقع لا استعمال البيانات: ينسخ الناشر المواعيد من الإعلان
  الرسمي أو من لوحة المحطة، فيدخلها في اللوحة كما يدخل أي خبر.
- **لا بذرة** — `supabase/sql/trains-section.sql` يوسّع القيد ليقبل `trains` ويزكي صف
  القسم وحده. لا تُذرَع مواعيد وهمية: بطاقة بموعد قديم تُضلّل مسافرًا، والجدول يتغيّر كل
  بضعة أشهر ولا يمكن التحقق منه من هذا المشروع.
- **الحقول** — `title` على مثال «906 — القاهرة ← الإسكندرية»، و`date` (حقل «التاريخ كما
  يظهر» = `event_date`) **تاريخ سريان الجدول** بصيغة `2026-10-04`، و`link` صفحة المواعيد
  الرسمية، و`body` ملاحظات أطول (أرقام الحجز، شروط الخصم). أسطر `fields` المتعارف عليها:
  `رقم`، `النوع`، `من`، `إلى`، `قيام`، `وصول`، `المدة`، `الوقفات`، `الأسعار`، `الأيام`
  (عشرة أسطر هي حدّ الناشر، لكلٍّ أربعمئة حرف)، والأسماء تُقرأ مطويّة كما يطويها
  `searchFold` فلا تفرق الهمزة والتاء المربوطة؛ وما عداها يظهر في نهاية البطاقة كما كُتب.
- **التنبيه لا الادّعاء** — يعرض التطبيق تاريخ السريان، ويُنَبّه بعد ثلاثين يومًا عليه
  (`trains_stale`)، ويفتح «افتح المواعيد الرسمية» من `link`، ويذيّل القائمة بتنبيه
  `trains_disclaimer` بأن الشاشة معاونة لا مصدر رسمي.
- **البحث والتحديث** — يطابق البحث رقمَ القطار بالأرقام الهندية والميلادية جميعًا، ويقرأ
  المحطات والوسوم. زر التحديث والسحب يمرّان إلى الشبكة بلا قراءة من ذاكرة OkHttp
  (`Http.text(…, noCache = true)`)، ويعيدان قراءة `index.json` كذلك، فلا يحتاج القارئ
  إعادة تشغيل التطبيق ليظهر قسمٌ أضيف أو جدولٌ حَدِّث.
- **نسخة التطبيق القديمة** التي لا تعرف `trains` لا تفقد القسم: `Layout.from` يردّه إلى
  `list`، فتظهر الرحلات بحقولها كما كُتبت — بلا تجميع ولا ترتيب بالوقت، لا بلا محتوى.

## صيغة ملف القسم

```json
{
  "schemaVersion": 1,
  "sectionId": "village_news",
  "updatedAt": "2026-09-28",
  "items": [
    {
      "id": "vn-14",
      "title": "افتتاح نقطة البريد",
      "subtitle": "خدمة جديدة لسكان القرية",
      "image": "assets/news.svg",
      "imageCredit": "رسم توضيحي — CC0",
      "date": "2026-09-26",
      "tags": ["خدمات"],
      "pinned": false,
      "breaking": false,
      "link": "https://example.com/original-report",
      "source": { "name": "اسم الجهة", "url": "https://example.com/original-report" },
      "fields": { "الموقع": "وسط القرية", "الوقت": "10 صباحًا" },
      "attachments": [
        { "type": "image", "url": "assets/village.svg", "label": "منظر عام" },
        { "type": "video", "url": "https://hrsrtvrrpnwxqhadxhfg.supabase.co/storage/v1/object/public/media/village_news/ab12/clip.mp4",
          "poster": "assets/village.svg", "duration": 95 }
      ],
      "body": "<p>فقرة أو فقرات. يُسمح بعناصر: p, h2, h3, ul, ol, li, a, strong, em, blockquote.</p>"
    }
  ]
}
```

### `attachments` — الوسائط المرفوعة مثل منشور فيسبوك

| الحقل | إلزامي | الوصف |
|---|---|---|
| `type` | لا | `image` أو `video` أو `audio`. يُستنتج من امتداد الملف لو غاب أو كان خاطئًا. |
| `url` | **نعم** | رابط `http(s)` كامل. مسارات نسبية مقبولة أيضًا وتُحوَّل إلى مطلقة مقابل عنوان الصفحة. |
| `poster` | اختيار | صورة مصغّرة للفيديو. |
| `label` | اختيار | وصف قصير يظهر مع الوسائط. |
| `duration` | اختيار | بالثواني؛ يستخدمه التطبيق في شارة المدة. |

- الصور فقط ← معرض يمرّر أفقيًا باللمس داخل التطبيق. فيديو/صوت ← مشغّل مدمج (media3) يعمل
  داخل بطاقة الخبر، بلا WebView وبلا أي تتبّع.
- لا `attachments`؟ يُقرأ وسم `<video>`/`<audio>` داخل `data-ab-body` في وضع Blogger/WordPress.
- `image` العلوي هو الغلاف؛ إن تركته فارغًا استخدم التطبيق أول صورة من `attachments` غلافًا
  ولا يكرّرها أسفل النص.
- التطبيق يعرض الوسائط فقط ولا يرفع شيئًا إطلاقًا — الرفع محصور في `dashboard.html`.

قواعد مهمة:

- `id` ثابت ولا يُعاد استخدامه؛ يغيّره محرّر آخر يكسر «المقروء» والإشعارات.
- `date` بصيغة `YYYY-MM-DD` (أو `YYYY-MM`).
- `breaking: true` يعني خبرًا مهمًا جدًا؛ لا تستخدمه لكل مقال حتى لا يتحوّل التطبيق إلى مزعج.
- الخبر المنقول من جهة أخرى: ضع `link` و`source` واملأ `body` بملخّص من عندك، لا بنص المصدر.
- الصور هنا SVG موضعية placeholders بحرية CC0؛ استبدلها بصور تملكها أو مرخّصة بتصريح صريح، وحافظ على `imageCredit`.
- القيم `…` في `data/prices/*.json` مقصودة إلى أن يعمل GitHub Action ويملؤها بالأرقام الحقيقية.

## قراءة التطبيق لنفس الصفحة (بدل JSON)

لو فضّلت Blogger أو WordPress بدل GitHub Pages، فالصفحةHTML وحدها تكفي: التطبيق
يبحث عن أي عنصر فيه `data-ab-id` ويقرأ السمات. نفس أسماء الحقول أعلاه، والسمات
`data-ab-source-name` و`data-ab-source-url` و`data-ab-image-credit` و`data-ab-pinned`
و`data-ab-breaking`، وكل `data-ab-f-<اسم-الحقل>` لحقل إضافي، و`data-ab-body` على عنصر
يحتوي متن المقال. المسافة في اسم الحقل تُكتب شرطة (`data-ab-f-عدد-الفصول`)؛ التطبيق
يعيدها مسافة عند العرض. لهذا السبب لا تحتاج Jsoup أن تخمّن أي جزء من الصفحة مقالًا
ولا تُستخرج بيانات من تخطيط موقع غيرك — كل شيء معلَّم صراحةً في صفحتك أنت.

### 4) أي الأقسام تُكتب آليًا؟

الناشر يكتب عناصر الأقسام التي في `sections` تكون `source_kind = 'json'` و

اسمها في `index.json` فقط، والتطبيق يجلب مصادرها الحيّة بنفسه.

- **انتبه**: أول تشغيل للناشر يستبدل محتوى ملفات الأقسام المُدارة بما في جدول `items`.

### 6) ما الذي ينقّيه الناشر قبل الكتابة؟

الصفحة العامة تحقِل `body` بـ `innerHTML`، لذلك يمرّ المتن على قائمة بيضاء:
عناصر `p, br, h2, h3, h4, strong, b, em, i, u, ul, ol, li, a, blockquote, span` فقط،
وبلا سمات عدا `href` على `<a>` بشرط أن تبدأ بـ `http:`/`https:`/`mailto:` — فتُحذف
`<script>` و`on*=` و`javascript:` وحتى وسم الإغلاق اليتيم الذي كان سيتبقّى. روابط الوسائط
تقبل `http(s)` فقط، و`type` يُصحَّح من الامتداد، و`path` الداخلي يُستبعد من JSON العام.
المعاينة في اللوحة تستخدم نفس القائمة البيضاء، فلا مفاجأة بين ما تراه وما يُنشر.

**الروابط تُكتشف تلقائيًا:** اكتب العنوان كنص عادي داخل المتن (`www.example.com` أو
`https://example.com/a?x=1` أو `info@example.com`) وسيقوم الناشر بتحويله إلى `<a>` بـ
`rel="noopener noreferrer nofollow"`، والمعاينة في اللوحة والتطبيق يريانها رابطًا قابلًا
للنقر بالطريقة نفسها. ما هو داخل رابط موجود أصلًا لا يُمسّ، والترقيم اللاحق (مثل `.` أو `،` أو `)` )
يبقى خارج الرابط — إلا أقواسًا متوازنة داخل العنوان نفسه مثل
`https://ar.wikipedia.org/wiki/_(عزبة_بدوي)` فتبقى داخله. **وتُعرض باسم مقروء بدل العنوان
المُشفَّر:** اسم الصفحة نفسه إن وُجد (`BBC News عربي: الرئيسية`)، وإلا النطاق ثم آخر مقطع
مفيد في المسار (`ar.wikipedia.org › بدوي (عزبة)`)، مع العنوان كاملًا في سمة `title` عند
المرور بالفأرة.

**من أين يأتي اسم الصفحة؟** الأسماء المحفوظة في جدول `link_previews`: أول نشر بعد إضافة رابط
يطلب الصفحة مرة واحدة من داخل الـ Action (لا CORS هناك) ويقرأ `og:title`/`og:site_name` أو
`<title>`، ثم يحفظ النتيجة ويستعملها في كل نشر لاحق بلا طلب جديد. الحدود: ٨ روابط لكل
تشغيل، ٨ ثوانٍ لكل طلب، وصالحة ١٢٠ يومًا (٣٠ يومًا للنجاح الفاشل فلا يُعاد طرق الباب في كل
دقيقة)، وتُتخطّى الخطوة كلها إن كان الجدول غير موجود أو تعذّر الوصول إليه — النشر لا يتعطّل
مطلقًا بسبب رابط. لا يُطلب إلا `http(s)` عام: تُرفض `data:`/`javascript:` والعناوين المحلية
مثل `127.0.0.1` و`169.254.169.254`. المعاينة في اللوحة تقرأ الجدول نفسه فتعرض الاسم الذي
سيراه القارئ في التطبيق. العناوين والحقول (`fields`) يُنشر عنها
نصًا عاديًا عن قصد (بلا وسوم)، لكن تطبيق أندرويد يتعرّف على العنوان داخلها أثناء العرض ويجعله
قابلًا للنقر بنفس القاعدة، فلا حاجة لتحريرها وسومًا.

في الـ SQL وخطط للانتقال إلى الخطة المدفوعة.

## كيف تُحدِّث المحتوى

**كل شيء من اللوحة:** افتح `dashboard.html` ← احفظ الاتصال ← ادخل ← حرّر القسم/العنصر
واسحب صوره وفيديوهاته ← «حفظ» أو «حفظ ونشر». الناشر يعمل كل ٥ دقائق تلقائيًا، ولا تحتاج
أي مفتاح GitHub في اللوحة؛ إن استعجلت، شغّل `publish.yml` من رابط «نشر فوري (GitHub)» أعلى اللوحة.

**لقسم تفضّله ثابتًا** (مثل `about`): اترك `items_source = 'file'` وعدّل ملفه في المستودع
مباشرة؛ اللوحة تعرضه لكن لا تكتب عناصره.

**للاختبار محليًا** قبل الرفع، شغّل سيرفرًا ثابتًا من مجلد `web`:

```bash
npx --yes serve -l 8080 .        # ثم افتح http://localhost:8080
```

لا تفتح الصفحة بـ `file://` لأن المتصفح يمنع `fetch` من قراءة JSON من القرص.

### أمان مفاتيح الوصول

- مفتاح `anon` عامّ بطبعه، ولا يُعطى صلاحية بدون جلسة مستخدم مطابق لـ `admin_emails`.
- `service_role` لا يعيش إلا في أسرار GitHub؛ لا تضعه في `dashboard.html` ولا في أي commit.
- مفتاح GitHub الشخصي لم يعد له وجود في اللوحة: لا تُرسل أي طلب إلى `api.github.com` من
  المتصفح، ولا يُخزَّن أي token في `localStorage`. النشر مجدول في المستودع، والتشغيل اليدوي
  يتم في موقع GitHub بجلسته هو.
- صفحة اللوحة تحمل `noindex, nofollow`، لكنها ليست محمية بكلمة مرور على مستوى المسار —
  الحماية كلها في RLS وفي قائمة `admin_emails`.
