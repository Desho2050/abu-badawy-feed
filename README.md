# صفحة قرية أبو بدوي — مصدر المحتوى للتطبيق

هذه المجلد هو كل ما يُرفع إلى GitHub Pages. التطبيق لا يخزّن أي محتوى داخليًا؛
كل الأقسام والعناصر تأتي من ملفات JSON هنا، والصفحة HTML تعرض نفس البيانات
بصيغة مقروءة للإنسان ومعلَّمة صراحةً ليقرأها التطبيق.

## بنية `data/index.json`

```jsonc
{
  "schemaVersion": 1,
  "generatedAt": "2026-09-28T06:00:00Z",
  "notice": "نص شريط أعلى الصفحة (صيانة/توقف مؤقت)، أو احذفه.",
  "brand": { "name": "قرية أبو بدوي", "tagline": "…", "logoUrl": "assets/logo.svg",
             "primaryColor": "#00696E", "supportEmail": "you@example.com" },
  "digest": { "defaultSections": ["village_news"], "hour": 7, "minute": 30 },
  "prices": { "fxUrl": "data/prices/fx.json", "goldUrl": "data/prices/gold.json",
              "liveFxApi": "…", "liveGoldApi": "…" },
  "location": { "name": "مركز بيلا، كفر الشيخ", "latitude": 31.1728,
                "longitude": 31.2210, "timezone": "Africa/Cairo" },
  "legal": { "privacy": { "title": "سياسة الخصوصية", "url": "data/legal/privacy.json" },
             "terms":   { "title": "شروط الاستخدام", "url": "data/legal/terms.json" } },
  "sections": [
    { "id": "village_news", "title": "أخبار القرية", "icon": "newspaper",
      "layout": "list", "order": 40, "home": true, "enabled": true,
      "source": { "kind": "json", "url": "data/sections/village_news.json" },
      "notifications": { "default": true, "breaking": false } }
  ]
}
```

الحقول الاختيارية لقسم: `subtitle`، و`image` (صورة غلاف تظهر في رأس شاشة القسم بالتطبيق؛
تُرفع من اللوحة وتُخزَّن في `sections.cover_image`)، و`source.kind` أحد
`json | html | rss | fx | gold | inline | prayer | weather | converter | calendar`، و`inlineItems` عندما يكون المصدر `inline`،
و`"managedBy": "admin"` التي تعني أن لوحة الإدارة هي التي تكتب هذا الملف (انظر قسم لوحة الإدارة).

كتلة `location` اختيارية: يحفظها الناشر من `app_settings.location`، ومنها يحسب التطبيق
مواقيت الصلاة والتقويم الهجري ويجلب الأرصاد. إن غابت أو كانت إحداثيات غير صالحة يستخدم التطبيق
موضع القرية الافتراضي (مركز بيلا، كفر الشيخ) — فلا يكسر حذفُها شيئًا.

### إضافة قسم جديد دون تعديل التطبيق

1. أضف عنصرًا إلى `sections` بـ `id` لاتيني فريد و`order` و`icon` من الأيقونات المعروفة
   (`newspaper`, `landmark`, `person`, `coins`, `gold`, `offer`, `megaphone`, `ball`, `globe`, `info`, `obituary`).
2. أنشئ `data/sections/<id>.json`.
3. ارفع الملفين. التطبيق يرسم القسم تلقائيًا في الرئيسية والدرج والإشعارات.
4. لإخفاء قسم مؤقتًا: `"enabled": false` — لا يحتاج حذفًا ولا إصدارًا جديدًا.

| `calendar` | تقويم ميلادي بهوامش هجرية، ومناسبات، ومحوّل بين التقويمين | لا عناصر — يحسبه التطبيق من Aladhan حسب `location` |

### قسم «تطبيقاتي» (`layout: apps`)

ثلاث اصطلاحات تجعل العنصر تطبيقًا لا خبرًا، بلا تعديل في التطبيق:

- **الصورة** — أيقونة التطبيق: مربّعة لا تضيق عن 192×192، تُرفع من اللوحة أو يوضع رابطها المباشر.
- **رابط خارجي** — صفحة المتجر أو أي رابط يخص التطبيق؛ يرسمه التطبيق زرَّ «افتح التطبيق»
  فيرسل الرابط إلى نظام التشغيل، فلا إذن جديد ولا تنزيل داخل التطبيق.
- **حقل `المميزات`** — سطر واحد تفصل الفواصل بين مزاياه (`،` أو `,` أو `؛` أو `|`)، فيعرضها
  التطبيق سطورًا تحت الوصف: أول ستٍّ في البطاقة، والبقية في صفحة الوصف عند النقر عليها.

بقية الحقول (`المطوّر`/`الحزمة`/`آخر تحديث`…) تظهر أسطرًا بعد المميزات، والنقر على البطاقة
يفتح الوصف كاملًا بكل المرفقات. البذرة الجاهزة في `supabase/sql/my-apps-section.sql`.

### قسم «قنوات البرمجة» (`layout: channels`)

بنفس بساطة `apps`، لكن للروابط الخارجية: بطاقة لكل قناة بشعارها (أو رمز دائري
إن تُركت الصورة فارغة)، وشارة المنصة المحسوبة من الرابط (يوتيوب/تليجرام/فيسبوك/
تيك توك/إنستجرام/إكس/واتساب، وما عداها «الموقع»)، والوصف، ووسوم المواضيع، وزر
«افتح القناة على يوتيوب» يرسل الرابط إلى نظام التشغيل — فلا إذن جديد في التطبيق،
ولا WebView، ولا تتبّع. بالنقر على البطاقة يفتح الوصف كاملًا كالعادة.

- **الاصطلاحات**: `الرابط الخارجي` = صفحة القناة، و`الوسوم` (أو حقل `المواضيع`)
  = مواضيعها، و`حقول إضافية` = اللغة والفئة العمرية ومعرّف القناة `UC…`.
- **الروابط**: لا تُنشر قبل فتحها والتأكد منها؛ معرّف القناة يبقى مرجعًا إن غيّر
  صاحبها الاسم المستعار. البذرة الموثّقة (ست قنوات عربية لتعليم الأطفال) في
  `supabase/sql/code-channels-section.sql`.
- **المسؤولية**: التطبيق يعرض روابط ولا يتحكّم في محتوى القنوات، فتختم البطاقات
  بسطر `channels_disclaimer` يوصي بمتابعة الأبناء.

### قسم «محافظة كفر الشيخ» (`layout: list` — محتوى بلا كود)

عشرون عنصرًا list، كل عنصر جانب من معلومات المحافظة (الموقع والحدود، الطبوغرافيا،
المناخ، المراكز العشرة، السكان وتعداداتهم، التاريخ الإداري، الاقتصاد، الجامعة،
بحيرة البرلس، مصيف بلطيم، معركة البرلس، دسوق، العاصمة، الطرق، مركز بيلا، الأعلام،
المحافظون، بطاقة سريعة). لا تعديل في التطبيق ولا في اللوحة ولا في الناشر: تخطيط
`list` ومصدر `json` يعملان من قبل، فالتسليم كله في `supabase/sql/governorate-section.sql`.

- **المصدر إلزامي**: ويكيبيديا نصّها مرخّص CC BY-SA 4.0 ويلزمها النسب، لذلك كل عنصر
  يحمل `اسم المصدر` و`رابط المصدر` إلى مقالته، وفي آخر متنه جملة «المصدر»، وزر
  «افتح المصدر» في صفحة العنصر يفتح المقالة. المتن ملخَّص لا منسوخ حرفيًا.
- **الصور**: كلها من ويكيميديا كومنز برخصة حرة، و`حقل النسب` (`image_credit`) يكتب
  المرخّص والرخصة، والتطبيق يعرضه تحت الصورة دائمًا. أي صورة تُضاف لاحقًا بلا نسب
  يرفعها فحص التحقّق في نهاية الملف تحذيرًا.
- **ما تضارب في المصدر ذُكر كما هو**: تعداد 2015 ورد في المقالة على رقمين
  (3,172,753 في الصندوق و3,941,293 في المتن) فيعتمد رقم 2024 (3,740,624) ويُذكر
  الآخران؛ وكذلك «13 مدينة» مقابل 14 في الصندوق، وعرض بوغاز البرلس في مقالة
  المحافظة مقابل مقالة البحيرة.
- **التقادم**: اسم المحافظ يتغيّر بقرار جمهوري، وعدد السكان تُحدِّثه التقديرات؛
  عنصر «محافظو كفر الشيخ» يشرح هذا صراحةً في آخر متنه، فحدِّثه من اللوحة عند الشك
  بدل إعادة تشغيل الملف (إعادة التشغيل لا تغيّر عنصرًا موجودًا).

### أخبار العالم والرياضة: `news.yml` يجلب وينشر في نفس التشغيل

قسمَا «أخبار عالمية» (`world_news`) و«أخبار الرياضة» (`sports`) لا يُحرَّران يدويًا كل يوم:
`scripts/sync-news.mjs` يجلب ست خلاصات RSS عربية رسمية كل ١٥ دقيقة ويكتب العناصر في
جدول `items` — فيبقى مصدر الحقيقة واحدًا (القاعدة)، وتراه اللوحة وتحرّره كأي عنصر.

| التغذية | القسم | الصورة |
|---|---|---|
| بي بي سي عربي | عالم | `media:thumbnail` |
| فرانس 24 | عالم | `media:thumbnail` + `enclosure` |
| سكاي نيوز عربية | عالم (ورياضة لما كان المسار `/sport`) | `enclosure` |
| الجزيرة نت | عالم (ورياضة لما كان المسار `/sports`) | `og:image` من الصفحة |
| سبوتنيك عربي | عالم | `og:image` من الصفحة |
| الرياضية | رياضة | `main_image` |

- **المِلكية**: كل عنصر آلي يبدأ الslug عنده بـ `rss-` (بصمة الرابط)، فلا يمسّ السكريبت
  عنصرًا كتبه ناشر القرية. الفلترة تتم بالبادئة في JS بعد قراءة القسم كاملًا، لا بفلتر
  `like` في REST (النقطة فيها حرف لا وايلد، وهو ما ضاعف الأخبار جولةً كاملة)، وتُحذف أي
  نسخ مكرّرة تلقائيًا — وضبط `supabase/sql/rss-slug-unique.sql` يمنع المكرّر بقيد في القاعدة.
  وللمدراء سيطرة تبقى بعد كل جولة: `pinned` و`breaking` لا تُرسل في التحديث،
  و`status = archived` تعني «لا تُحدّث هذا الخبر أبدًا».
- **أربعة في البطاقة**: العنوان في `title`، والملخص في `subtitle`، والصورة في `image`
  مع نسبها في `image_credit`، ورابط المصدر في `link` + `source_name` + `source_url`
  — وهو زر «افتح المصدر» في صفحة العنصر، فيقرأ القارئ الخبر عند من كتبه.
- **حدود معقولة**: ٤٠ عنصرًا لكل قسم في الجولة، و١٢ لكل تغذية حتى لا يبتلع مصدرٌ القسم،
  وأحدث ٦٠ فقط تُبقى في القاعدة (الناشر ينشر ٨٠ بحدّه `MAX_ITEMS`)، ولا خبر أقدم من
  أربعة أيام. الصور الناقصة تُجلب من `og:image` بحدّ ١٢ صفحة في الجولة وتُخزَّن في
  `link_previews` فلا يُجلب رابط مرتين.
- **NewsAPI اختياري**: الخطة المجانية ١٠٠ طلب/يوم والدورية ٩٦ جولة، فيُستقصى في أول ثماني
  دقائق من كل ساعة فقط (٤٨ طلبًا/يوم). بلا `NEWS_API_KEY` في الأسرار يعمل النظام بالخلاصات
  وحدها، وهذا يكفي؛ لا يوضع المفتاح في التطبيق ولا في اللوحة أبدًا.
- **التأخير الظاهر**: لا يوجد — `news.yml` يشغّل `publish.mjs` ويدفع `data/` في نفس التشغيل،
  فالخبر يصل التطبيق خلال دورته. يبقى `publish.mjs` هو المولّد الوحيد للملفات في الحالتين،
  فلا مصدر الحقيقة الثاني غير القاعدة.
- **جدولة GitHub متأخرة فعليًا**: الكرون هنا لا يحترم توقيته؛ `publish.yml` المجدول كل خمس
  دقائق شُغِّل جدوليًا سبع مرات في يومين (قياس ٢٠٢٦-١٠-٠٤). لذلك يضيف `news.yml` «تتابعًا»:
  كل تشغيل ينتظر حدّ الربع ساعة ثم يرسل `workflow_dispatch` لنفسه، فيصير الدور كل ١٥ دقيقة
  مهما تأخر الكرون. التتابع اختياري: يتفعّل بمجرد إضافة سرّ `RELAY_TOKEN` (مفتاح شخصي
  من نوع fine-grained، صلاحيته Actions: Read and writes على هذا المستودع وحده). بدونه يعمل الكرون وحده.
- **تحقّق قبل النشر**: `node .github/scripts/sync-news.mjs --dry-run` يطبع ما سيُكتب بلا
  كتابة، و`--section=sports` لقسم واحد.

### قسم «التقويم الهجري» (`layout: calendar`)

لا عناصر له ولا ملف تغذية: التطبيق يحسبه وحده من Aladhan بنفس `method=5` ومن نفس
`location` اللذين تحسب منهما مواقيت الصلاة، فلا يتناقض الشهر الهجري في التقويم مع
عدّاد المواقيت ولا مع إعلان دار الإفتاء المحلي.

- **الشبكة** — شهر ميلادي كامل يبدأ السبت (أول أيام الأسبوع في التقويم العربي)، وفي كل
  خلية اليوم الميلادي ففوقه نظيره الهجري. اليوم الحالي مميّز بلون الحشو الأساسي،
  والمناسبة بشرطة سفلى؛ والنقر على الخلية يملأ خانات التحويل باليوم المختار.
- **المناسبات** — جدول عربي منتقى في التطبيق (`OCCASIONS`) مفتّح بيوم الشهر الهجري
  وشهره: رأس السنة الهجرية، عاشوراء، المولد النبوي، الإسراء والمعراج، ليلة البراءة،
  أول رمضان، ليلة القدر، عيد الفطر، يوم عرفة، عيد الأضحى وأيام التشريق. تظهر في الشهر
  قائمةً مستقلة تحت الشبكة بتاريخها الميلادي، لأن قائمة الأعياد التي يرجعها Aladhan
  إنجليزية ومزدحمة بملاحظات فقهية لا تصلح للعرض.
- **التحويل** — اتجاهان (ميلادي ← هجري وهجري ← ميلادي) باسم اليوم العربي في النتيجة،
  بخانات شهر وسنة تنقل كاملًا. الحساب تقديري، والشهر الهجري ثبوتُه بالرؤية؛ النص
  `calendar_disclaimer` يوضح ذلك أسفل الشاشة.
- **عند انقطاع الإنترنت** — يُخزَّن لكل شهر نصّ استجابته (`calendar.<yyyy-MM>.raw`) ولكل
  تاريخ محوَّل نسخته، فتُعرض آخر نسخة مع شارة «غير متصل» بدل أن تفارغ الشاشة.
- **التدريج** — نسخة قديمة من التطبيق لا تعرف `calendar` تعرض القسم كقائمة فارغة، والناشر
  القديم يحوّل تخطيطه إلى `list` بلا خطأ. البذرة والقيود في `supabase/sql/calendar-section.sql`.

## صيغة ملف القسم

```json
{
  "schemaVersion": 1,
```

### `attachments` — الوسائط المرفوعة مثل منشور فيسبوك

| الحقل | إلزامي | الوصف |
|---|---|---|
| `type` | لا | `image` أو `video` أو `audio`. يُستنتج من امتداد الملف لو غاب أو كان خاطئًا. |
| `url` | **نعم** | رابط `http(s)` كامل. مسارات نسبية مقبولة أيضًا وتُحوَّل إلى مطلقة مقابل عنوان الصفحة. |
| `poster` | اختيار | صورة مصغّرة للفيديو. |
| `label` | اختيار | وصف قصير يظهر مع الوسائط. |
| `duration` | اختيار | بالثواني؛ يستخدمه التطبيق في شارة المدة. |

- الصور فقط ← معرض يمرّر أفقيًا باللمس داخل التطبيق. فيديو/صوت ← مشغّل مدمج (media3) يعمل
  داخل بطاقة الخبر، بلا WebView وبلا أي تتبّع.
- لا `attachments`؟ يُقرأ وسم `<video>`/`<audio>` داخل `data-ab-body` في وضع Blogger/WordPress.
- `image` العلوي هو الغلاف؛ إن تركته فارغًا استخدم التطبيق أول صورة من `attachments` غلافًا
  ولا يكرّرها أسفل النص.
- التطبيق يعرض الوسائط فقط ولا يرفع شيئًا إطلاقًا — الرفع محصور في `dashboard.html`.

قواعد مهمة:

- `id` ثابت ولا يُعاد استخدامه؛ يغيّره محرّر آخر يكسر «المقروء» والإشعارات.
- `date` بصيغة `YYYY-MM-DD` (أو `YYYY-MM`).
- `breaking: true` يعني خبرًا مهمًا جدًا؛ لا تستخدمه لكل مقال حتى لا يتحوّل التطبيق إلى مزعج.
- الخبر المنقول من جهة أخرى: ضع `link` و`source` واملأ `body` بملخّص من عندك، لا بنص المصدر.
- الصور هنا SVG موضعية placeholders بحرية CC0؛ استبدلها بصور تملكها أو مرخّصة بتصريح صريح، وحافظ على `imageCredit`.
- القيم `…` في `data/prices/*.json` مقصودة إلى أن يعمل GitHub Action ويملؤها بالأرقام الحقيقية.

### 4) أي الأقسام تُكتب آليًا؟

الناشر يكتب عناصر الأقسام التي في `sections` تكون `source_kind = 'json'` و
`items_source = 'admin'`، ويكتب `data/index.json` منه أيضًا بقائمة الأقسام والعلامة
والقوانين والأسعار. القسم الذي `items_source = 'file'` يبقى ملفه كما هو في المستودع.
في `data/index.json` يترجم الناشر ذلك إلى `"managedBy": "admin"`.

أقسام `prayer` و`weather` و`converter` و`calendar` لا تُكتب لها ملفات إطلاقًا (ليست `json`)؛ يظهر
اسمها في `index.json` فقط، والتطبيق يجلب مصادرها الحيّة بنفسه.

- **انتبه**: أول تشغيل للناشر يستبدل محتوى ملفات الأقسام المُدارة بما في جدول `items`.
  انقل المحتوى الذي تريد الإبقاء عليه إلى اللوحة أولًا (أو شغّل `tools/gen-seed-sql.mjs`
  لتوليد `supabase/sql/seed-content.sql` من الملفات الحالية)، أو اترك القسم `items_source = 'file'`.
- إذا لم يجد للقسم أي عنصر منشورًا تُرِك الملف كما هو وطُبع `-- NOTICE:` بدل أن يمسحه الناشر؛
  لإفراغه فعلًا شغّله بـ `ALLOW_EMPTY=1`.
- `MAX_ITEMS` (افتراضي ٨٠) يحدّ عدد العناصر في القسم، و`sort_order` يقدّم عنصرًا على آخر.

### 6) ما الذي ينقّيه الناشر قبل الكتابة؟

الصفحة العامة تحقِل `body` بـ `innerHTML`، لذلك يمرّ المتن على قائمة بيضاء:
عناصر `p, br, h2, h3, h4, strong, b, em, i, u, ul, ol, li, a, blockquote, span` فقط،
وبلا سمات عدا `href` على `<a>` بشرط أن تبدأ بـ `http:`/`https:`/`mailto:` — فتُحذف
`<script>` و`on*=` و`javascript:` وحتى وسم الإغلاق اليتيم الذي كان سيتبقّى. روابط الوسائط
تقبل `http(s)` فقط، و`type` يُصحَّح من الامتداد، و`path` الداخلي يُستبعد من JSON العام.
المعاينة في اللوحة تستخدم نفس القائمة البيضاء، فلا مفاجأة بين ما تراه وما يُنشر.

**الروابط تُكتشف تلقائيًا:** اكتب العنوان كنص عادي داخل المتن (`www.example.com` أو
`https://example.com/a?x=1` أو `info@example.com`) وسيقوم الناشر بتحويله إلى `<a>` بـ
`rel="noopener noreferrer nofollow"`، والمعاينة في اللوحة والتطبيق يريانها رابطًا قابلًا
للنقر بالطريقة نفسها. ما هو داخل رابط موجود أصلًا لا يُمسّ، والترقيم اللاحق (مثل `.` أو `،` أو `)` )
يبقى خارج الرابط — إلا أقواسًا متوازنة داخل العنوان نفسه مثل
`https://ar.wikipedia.org/wiki/_(عزبة_بدوي)` فتبقى داخله. **وتُعرض باسم مقروء بدل العنوان
المُشفَّر:** اسم الصفحة نفسه إن وُجد (`BBC News عربي: الرئيسية`)، وإلا النطاق ثم آخر مقطع
مفيد في المسار (`ar.wikipedia.org › بدوي (عزبة)`)، مع العنوان كاملًا في سمة `title` عند
المرور بالفأرة.

**من أين يأتي اسم الصفحة؟** الأسماء المحفوظة في جدول `link_previews`: أول نشر بعد إضافة رابط
يطلب الصفحة مرة واحدة من داخل الـ Action (لا CORS هناك) ويقرأ `og:title`/`og:site_name` أو
`<title>`، ثم يحفظ النتيجة ويستعملها في كل نشر لاحق بلا طلب جديد. الحدود: ٨ روابط لكل
تشغيل، ٨ ثوانٍ لكل طلب، وصالحة ١٢٠ يومًا (٣٠ يومًا للنجاح الفاشل فلا يُعاد طرق الباب في كل
دقيقة)، وتُتخطّى الخطوة كلها إن كان الجدول غير موجود أو تعذّر الوصول إليه — النشر لا يتعطّل
مطلقًا بسبب رابط. لا يُطلب إلا `http(s)` عام: تُرفض `data:`/`javascript:` والعناوين المحلية
مثل `127.0.0.1` و`169.254.169.254`. المعاينة في اللوحة تقرأ الجدول نفسه فتعرض الاسم الذي
سيراه القارئ في التطبيق. العناوين والحقول (`fields`) يُنشر عنها
نصًا عاديًا عن قصد (بلا وسوم)، لكن تطبيق أندرويد يتعرّف على العنوان داخلها أثناء العرض ويجعله
قابلًا للنقر بنفس القاعدة، فلا حاجة لتحريرها وسومًا.

### 7) حدود خطة Free

١ جيجابايت قاعدة بيانات + ١ جيجابايت تخزين ملفات، و٥ جيجابايت نقل شهريًا، و٥٠٬٠٠٠ مستخدم
شهريًا بالمصادقة. المشروع المجاني يتوقف (pause) بعد سبعة أيام بلا نشاط، فيُستأنف بضغطة من
لوحة Supabase. الفيديو هو ما يستهلك النقل، لذلك حُدّد الملف الواحد بـ ٢٥ ميجابايت؛ للقارئ
العادي تكفي الصور، فاجعل الفيديو للمناسبات النادرة. لو تجاوزت الحدود ارفع `file_size_limit`
في الـ SQL وخطط للانتقال إلى الخطة المدفوعة.

## كيف تُحدِّث المحتوى

**كل شيء من اللوحة:** افتح `dashboard.html` ← احفظ الاتصال ← ادخل ← حرّر القسم/العنصر
واسحب صوره وفيديوهاته ← «حفظ» أو «حفظ ونشر». الناشر يعمل كل ٥ دقائق تلقائيًا، ولا تحتاج
أي مفتاح GitHub في اللوحة؛ إن استعجلت، شغّل `publish.yml` من رابط «نشر فوري (GitHub)» أعلى اللوحة.

**لقسم تفضّله ثابتًا** (مثل `about`): اترك `items_source = 'file'` وعدّل ملفه في المستودع
مباشرة؛ اللوحة تعرضه لكن لا تكتب عناصره.

**للاختبار محليًا** قبل الرفع، شغّل سيرفرًا ثابتًا من مجلد `web`:

```bash
npx --yes serve -l 8080 .        # ثم افتح http://localhost:8080
```

لا تفتح الصفحة بـ `file://` لأن المتصفح يمنع `fetch` من قراءة JSON من القرص.

### أمان مفاتيح الوصول

- مفتاح `anon` عامّ بطبعه، ولا يُعطى صلاحية بدون جلسة مستخدم مطابق لـ `admin_emails`.
- `service_role` لا يعيش إلا في أسرار GitHub؛ لا تضعه في `dashboard.html` ولا في أي commit.
- مفتاح GitHub الشخصي لم يعد له وجود في اللوحة: لا تُرسل أي طلب إلى `api.github.com` من
  المتصفح، ولا يُخزَّن أي token في `localStorage`. النشر مجدول في المستودع، والتشغيل اليدوي
  يتم في موقع GitHub بجلسته هو.
- صفحة اللوحة تحمل `noindex, nofollow`، لكنها ليست محمية بكلمة مرور على مستوى المسار —
  الحماية كلها في RLS وفي قائمة `admin_emails`.
